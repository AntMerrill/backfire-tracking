How the robots work

claude, 2026-11-09. John: "make the call... once you have made the call, you are ready to [log] out... clean up your own terminal... let the child process go, and rely on the callback to reinstate."

The idea in one line

Whoever hands off work ends right after the handoff. Whoever finishes work calls claude back. Nobody sits waiting, nobody sets a timer, and a window closes when its job is done.

One command: robot-run

robot-run [--exit-caller] <robot> <job.md> [tag]
  • job.md is a file in the hub, /srv/agents/swap/<date>/, named <date>_<topic>_<from>_to_<to>.md.
  • Each robot gets its own window and a plain-text log, ~/Desktop/claude/<date>/<robot>_<tag>_run.log, which John reads afterward.
  • --exit-caller starts the robot, then about 3 seconds later ends whoever ran the command (the nearest claude or opencode above it) together with that caller's window. That's the "make the call, then log out" step.
  • Switches: DRY=1 (print, start nothing) · NET=1 (the job may use the network it names) · NOCALLBACK=1 (no tag-back) · QUEUE=<file> (which queue the callback works from).

The loop

claude ──robot-run --exit-caller opie job──▶ Opie works          (claude's window closes)
                                              writes reply
Opie ──robot-run --exit-caller claude reply──▶ fresh claude         (Opie's window closes)
                                              checks reply on its witness
                                              adds one line to today's list
                                              starts next `open` job in night_queue.md
                                              (with --exit-caller, so its window closes too)
                                              queue empty → writes "queue empty", window closes
  • The callback claude is headless (claude.sh --token -p), so it keeps working unattended. Only one callback runs at a time (a lock); a second waits up to 10 minutes.
  • Perl and chromie can't start a hogan process themselves, so the window that started them does the tag-back as soon as their run ends.
  • The night queue is /srv/agents/swap/<date>/night_queue.md, one job per line: state | robot | job file | tag | net. States: open, started HH:MM, done, dropped. Only claude edits it.
  • Failures get handled on the spot (John 11-09). If a robot fails or stops partway, it still tags claude back. The callback reads the log, and if the fix fits the job's own rules (go slower, resume, skip a bad item), it writes a _retry1 job and puts it at the top of the queue. It retries once at most. Anything that needs John goes on the list as awaiting:john with the proposed fix written out.
  • Night rules for a callback claude: no publishing, posting, wiki edits, pushes, sudo or deletions, and nothing that needs John. Anything that needs him goes on the list as awaiting:john, and the callback stops.

Starting Perl and chromie without a password

Perl and chromie are separate Linux users, so starting them goes through sudo. One rule makes that password-free, and it allows only that one script:

hogan ALL=(%agents) NOPASSWD: /srv/agents/bin/agent_run.sh        # /etc/sudoers.d/agents-start

robot-run uses sudo -n, which never prompts, so it can't hang a terminal. It also refuses to start them until the rule is installed. The rule covers every member of group agents, so a new agent user is covered the moment she's made. The new-user script installs it (new_agent_user.sh, step 0) and --check confirms it. AGENTS.md lists it as the one sudo exception.

What to know

  • A killed caller leaves its transcript, not its last words. claude -p prints only at the end, so the caller's own log is empty. The session transcript is in ~/.claude/projects/, and the robot's log records --exit-caller: ending caller pid ….
  • Use --exit-caller only from a window that's there for one job. From John's own claude window it would close that window too. That's what the option does, so use it there only when John says to.
  • If a robot fails before tagging back, its window stays open on a shell (exec bash), so the failure can be seen. The reply file says what failed whenever the robot got that far.
